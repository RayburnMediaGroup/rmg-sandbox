Technology Stack

Layer Choice
FrameworkNext.js 16 App Router — never Pages Router. React 19. TypeScript always.
StylingTailwind CSS v4 — uses @import "tailwindcss", theme tokens inside @theme {}. No CSS modules, no styled-components.

02

Design System

Color — Dark-First, Dual-Theme Ready

Dark is the RMG default and primary look. Every site ships with a dark/light toggle — the same CSS token system used in this document. Light theme is warm parchment, never pure white corporate.

#0a0a0f — dark bg
#111118 — dark surface
#f5f3ef — light bg
#ffffff — light surface
#f59e0b — gold (dark)
#c27c00 — gold (light)
#0ea5e9 — ocean
#f97316 — sunset

One brand accent per client. Glass surfaces: rgba(255,255,255,0.04) dark / rgba(0,0,0,0.04) light. Accent shifts darker in light mode for legibility. See the CSS token pattern in this document.

Dual-Theme CSS Pattern (All Future Builds)

/* Dark-first token system — use on every build */
:root {
  /* Complete dark palette defined here */
  --bg: #0a0a0f;  --surface: #111118;  --surface2: #1a1a24;
  --text: #e8e8f0;  --muted: rgba(232,232,240,0.50);
  --accent: #f59e0b;  --accent-dim: rgba(245,158,11,0.15);
}

/* System preference: dark — beats un-stamped document */
@media (prefers-color-scheme: light) {
  :root:not([data-theme="dark"]) {
    --bg: #f5f3ef;  --surface: #ffffff;  --surface2: #f0ede8;
    --text: #18181f;  --muted: rgba(24,24,31,0.52);
    --accent: #c27c00;  --accent-dim: rgba(194,124,0,0.10);
  }
}

/* Explicit toggle — wins over system preference */
:root[data-theme="light"] {
  --bg: #f5f3ef;  --surface: #ffffff;  --surface2: #f0ede8;
  --text: #18181f;  --muted: rgba(24,24,31,0.52);
  --accent: #c27c00;  --accent-dim: rgba(194,124,0,0.10);
}

/* Required: body must have explicit background token */
body { background: var(--bg); color: var(--text); }

/* JS toggle button */
function toggleTheme() {
  const h = document.documentElement;
  h.dataset.theme = h.dataset.theme === 'dark' ? 'light' : 'dark';
  localStorage.setItem('theme', h.dataset.theme);
}
/* Restore saved preference on load (add to <head>): */
const t = localStorage.getItem('theme');
if (t) document.documentElement.dataset.theme = t;

Typography — Chosen Per Client, Never the Same Twice

Every site gets a font pair chosen for that brand — not a house font. Pick a display face that matches the industry's personality, pair it with a clean readable body face. Below are proven options, not requirements.

Cormorant Garamond — Luxury / Hospitality / Editorial Thin, elegant, high-end
Outfit — Modern / Tech / Services Clean, geometric, very legible
Space Mono — Labels / Eyebrows / Data UI Technical precision, monospaced

Research Google Fonts for each new client. Look at the industry: a roofing company might get a strong slab serif. A spa gets something thin and airy. A law firm gets a sharp transitional serif. The font is part of the brand — make it a conscious decision.

Visual Language

Rounded everywhere

Cards 1.25rem, buttons 9999px pill, badges 9999px.

Glass morphism

backdrop-filter blur(24px) saturate(180%) on cards and nav.

Layered depth

Sections alternate bg colors. Never flat single-tone pages.

Gradient text accents

Key words use text-sunset or text-ocean gradient clips.

Hover: lift + shadow

Cards translateY(-4px) + deeper shadow. Images scale(1.05).

Sticky glass nav

backdrop-filter as inline style — Tailwind v4 strips it from classes.

Trending Patterns to Use

Horizontal scroll strips

Mobile-first card rows. Always add padding-top + overflow-y:hidden.

Eyebrow → Display → Lead

Every section opens this way. Never skip the eyebrow label.

Stat / signal grids

3-col numbers with accent colors. Shows authority fast.

Editorial 2-col alternating

Image left + text right, then flip. FeaturedSection pattern.

Full-bleed video hero

Autoplay muted loop. Text overlay with display heading + CTA.

Floating card badges

Category, rating, or tag overlaid on card image — absolute positioned.

The Card Standard — Add to globals.css Day 1

This is locked. Never rewrite. Never add z-index, position, will-change, isolation, or contain to glass-card. See rmg-components for full component files.

/* ─── Glass Card ─────────────────────────────────── */
.glass-card {
  background: rgba(255, 255, 255, 0.04);
  backdrop-filter: blur(24px) saturate(180%);
  -webkit-backdrop-filter: blur(24px) saturate(180%);
  border: 1px solid rgba(255, 255, 255, 0.08);
  border-radius: 1.25rem;
  box-shadow: 0 8px 48px rgba(0,0,0,0.5),
              inset 0 1px 0 rgba(255,255,255,0.08);
  transition: all 0.4s cubic-bezier(0.16, 1, 0.3, 1);
}

.glass-card:hover {
  background: rgba(255, 255, 255, 0.07);
  border-color: rgba(255, 255, 255, 0.13);
  transform: translateY(-4px);
  box-shadow: 0 24px 80px rgba(0,0,0,0.6),
              inset 0 1px 0 rgba(255,255,255,0.12);
}

/* ─── Card image system ───────────────────────────── */
/* border-radius:inherit prevents GPU layer from      */
/* squaring corners during hover image zoom           */
.overflow-hidden > img {
  border-radius: inherit;
}
.glass-card > .overflow-hidden:first-child {
  border-radius: 1.25rem 1.25rem 0 0;
}

/* ─── Horizontal scroll strips ───────────────────── */
/* overflow-x:auto forces overflow-y:auto (CSS spec). */
/* padding-top:8px = room for hover lift inside clip. */
/* overflow-y:hidden = blocks two-finger vertical     */
/* scroll pushing cards into the clip zone.           */
.overflow-x-auto {
  padding-top: 8px;
  overflow-y: hidden;
}

JSX Pattern — Standard Card

<Link href="..." className="group block glass-card overflow-hidden h-full">
  <!-- Image wrapper: overflow-hidden + radius here, NOT on the card -->
  <div className="relative overflow-hidden aspect-[16/10]">
    <img
      src="..."
      alt="..."
      className="w-full h-full object-cover
                 transition-transform duration-700
                 group-hover:scale-105"
      loading="lazy"
      width={800}
      height={500}
    />
  </div>
  <div className="p-6">
    <!-- content -->
  </div>
</Link>

Build Workflow

Phase 1 — Scaffold

01

npx create-next-app@latest client-name-next --typescript --tailwind --app --no-src-dir --no-import-alias --yes

02

Delete all boilerplate. Add RMG card standard CSS to globals.css immediately.

03

Set up fonts in layout.tsx: Cormorant Garamond + Outfit + Space Mono via next/font/google.

04

gh repo create RayburnMediaGroup/client-name-next --public --source . --push then connect to Vercel.

Phase 2 — Content & Data

01

Audit the client's existing site with Harpoon at audit.rayburnmedia.com/?owner=1.

02

Pull all content into lib/data.ts — listings, cards, nav items, everything typed.

03

Copy all images to public/images/ immediately. Compress: max 1920px, cwebp q82.

Phase 3 — Build Order

01

Navbar — glass, sticky, mobile hamburger, backdrop-filter as inline style.

02

Hero — full-bleed image or video, display heading, CTA button.

03

Homepage sections — 2–4 key sections using glass cards and editorial layouts.

04

Footer then inner pages, then Schema/JsonLd on every page, then sitemap.

Phase 4 — Check Along the Way

→

Run Harpoon on the Vercel preview URL after each major section.

→

Check PageSpeed score. Target 90+ mobile.

→

npm run build locally before every push. Never push broken builds.

Critical Rules — Never Break

⚠ Invented Copy — Always Mark It

When a build requires placeholder titles, descriptions, or paragraphs before real client content exists, every invented line gets marked. No exceptions. The client must always know what is real and what needs to be replaced.

/* 1. Inline amber ⚠ on every invented string */
<h2>⚠ Roofing Solutions Built to Last</h2>
<p>⚠ Placeholder — replace with client-provided copy before launch.</p>

/* 2. Sitewide draft badge — add to layout.tsx on every SiteStack build */
<div style={{
  position: "fixed", bottom: 16, right: 16, zIndex: 9999,
  background: "#f59e0b", color: "#000",
  padding: "6px 14px", borderRadius: 9999,
  fontSize: "0.7rem", fontWeight: 700,
  letterSpacing: "0.1em", textTransform: "uppercase",
  pointerEvents: "none"
}}>
  ⚠ DRAFT — Copy Not Approved
</div>

Remove the layout badge only when the client has reviewed and signed off on all copy. Keep the inline ⚠ markers until final client approval — they survive in the git diff as a paper trail.

Never Do These

  • No Framer Motion. 148KB unused JS penalty. Use CSS + IntersectionObserver.
  • No overflow-hidden on section containers. Clips card hover lift. Only on image wrappers inside cards.
  • No z-index, position, will-change, isolation, or contain on glass-card. All cause clipping or blur bugs.
  • No base64. Causes session freeze and server errors. Reference files by path only.
  • No in-app browser tool. Always fails, wastes 15 minutes. Read code and ask user to verify instead.
  • No fabricated content. Only real client data or cited sources. Mark invented copy with ⚠ in SiteStack builds.
  • Navbar backdrop-filter must be inline style. Tailwind v4 strips it from CSS classes.
  • public/ is single source of truth. Copy ALL images there immediately. Never rely on Desktop or external drives.
  • npm run build must pass before every push. Never deploy a broken build.
  • Ask before any destructive action. Backup, confirm, then proceed.
  • Never touch best-of-cabo-next. Hostinger production. READ-ONLY reference.
  • Output files to ~/Desktop. No subfolders except CLAUDE DATA BACKUPS.
